# AI 集群可靠性建模与评估

围绕单个大规模训练作业，评估硬件故障、故障检测和恢复机制对**正确有效产出**的影响。系统将故障事件、可靠性机制、计算结果和优化收益分开管理，支持从千卡到五十万卡的规模分析。

**最新审核版本：2026-10-09。** 本轮报告包含 54 条故障事件、12 项可靠性机制、单项收益、六机制组合的 Shapley 贡献，以及五十万卡达到 90% 正确有效产出的条件分析。

## 当前基线与结果口径

| 项目 | 当前确认值 |
|---|---|
| 任务与周期 | 所有卡参与同一个作业，统计 30 天／720 小时 |
| 故障率锚点 | 万卡中断 MTBF 为 30 小时，故障率随卡数线性增加 |
| 故障类别占比 | 中断 96.6%、亚健康 2%、静默 1.4% |
| 检查点 | 计算 300 秒，阻塞保存 4 秒；停机期间不保存 |
| 自动恢复 | 尝试 3 分钟，成功率 99%；失败后额外人工恢复 2 小时 |
| 亚健康 | 降速损失单列；检出后保存当前进度，恢复不回滚 |
| 静默漏检 | 基线即时检出率为 0%，固定五天后发现，回到最后干净检查点 |

**运行可用度**衡量未处于全局停机的时间比例；**正确有效产出率**衡量月末保留的正确进度占 720 小时的比例。带错训练可能有较高运行可用度，却没有相应的正确产出。

五十万卡的候选优化方案中，启用重执行、进程重调度、50 域弹性、静默检测与 step 恢复，以及 60 秒计算／1 秒保存后：

| 全系统静默即时检出率 | 全局恢复尝试时间 | 平均正确有效产出率 | 单月达到 90% 的比例 |
|---|---:|---:|---:|
| 99% | 120 秒 | 91.91% | 85.2% |
| 99.5% | 120 秒 | 93.04% | 92.1% |
| 99.9% | 120 秒 | 94.01% | 98.3% |

以上每组模拟 10,000 次月任务，保留了 1% 恢复失败后额外人工两小时的假设。**平均达到 90% 不等于每个月都能达到 90%。** 组合参数不同于确认基线；DP 弹性等收益依赖对应机制覆盖和运行条件成立，不是生产 SLA。完整假设及置信区间见[目标分析](catalogs/review-2026-10-09/README.md)和[原始结果](catalogs/review-2026-10-09/target90-results.json)。

## 复现计算

需要 Node.js 18 或以上；本轮审核计算不依赖第三方库。

```sh
cd catalogs/review-2026-10-09
node analyze.cjs
node review.cjs
node target90.cjs
```

- `analyze.cjs`：重算机制收益、Shapley 贡献并生成 HTML。
- `review.cjs`：检查基线回归、时间守恒、事件汇总、机制覆盖及离线界面脚本。
- `target90.cjs`：重算五十万卡的 90% 目标扫描。
- [输入快照](catalogs/review-2026-10-09/inputs.json)和[基线引擎快照](catalogs/review-2026-10-09/reference.cjs)保留本轮评估依据。
